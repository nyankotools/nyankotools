その日の作業内容から、公式Xアカウント用のポスト文案を作成してください。

手順:

1. 今日の作業内容を把握する。
   - `git log --since=midnight --oneline` や `git status` で、今日コミットされた内容・未コミットの差分を確認する。
   - 補足指示 `$ARGUMENTS` が与えられていれば、それも内容把握に使う（デプロイ済みかどうか、対象ツール名など）。
2. 今日の作業がデプロイ済みかどうかを確認する。
   - `$ARGUMENTS` や会話内の発言から明らかであればそれに従う。
   - 不明な場合はユーザーに確認する（推測でデプロイ済みと書かない）。
3. デプロイ状況に応じて文面のトーンを変える。
   - デプロイ済み・新ツール公開など: 「公開しました」「使えるようになりました」等、告知トーン。
   - 未デプロイ・内部作業（リファクタリング、多言語対応の下準備など）: 「進めました」「近日公開予定」等、進捗報告トーン。
4. 以下を必ず含めて文案を作成する（どちらか欠けている案は不可）。
   - **リンクURL**: 具体的な新ツールが公開されている場合は `https://nyankotools.com/tools/<slug>/` のようにそのツールページを指す。ツール個別ページを指せない内容（内部リファクタリング等）の場合はトップページ `https://nyankotools.com/` を使う。
   - **ハッシュタグ**: `#個人開発 #便利ツール` を必ず末尾に付ける（表記・順序を変えない）。
5. 文体は日本語・カジュアルな個人開発者トーンで、絵文字は控えめに。X投稿として自然な長さ（URLとハッシュタグを含めて実用的な範囲）に収める。
6. 案は2〜3パターン用意し、ユーザーに選んでもらう形で提示する。
7. 内容が合うときは、リポジトリ・note記事への誘導案を1案だけ含める（Findy登録に向けた修正案 F-15 の方針）。毎回は入れず、宣伝が続かないようにする。
   - **入れてよい内容**: 開発ふりかえり・AI活用・技術的な工夫（CSP、CI、テスト、i18n設計など）に関わる回。新ツール告知だけの回は、誘導案なしでよい。
   - **誘導先**:
     - GitHubリポジトリ: `https://github.com/nyankotools/nyankotools`
     - note記事: `$ARGUMENTS` で記事のURLが与えられたときだけそのURLを使う。記事URLを推測して書かない。URLが不明で記事に誘導したい場合は、ユーザーに確認する（必要ならnoteのプロフィール `https://note.com/nyankotools` を案として示す）。
   - **形**: 本文の必須リンク（上記4）は変えず、誘導先URLを追加で1つだけ載せる（リンクは合計2つまで）。ハッシュタグの決まりは変えない。
   - **書き方の制約**: リポジトリは「閲覧・参照のみ」で公開しており（All rights reserved、Issue/PR不受付）、OSSではない。「OSS」「コントリビュート歓迎」「Issue/PRお待ちしています」など、貢献を募る表現は使わない。「ソースコードを公開しています」「開発の裏側をnoteに書きました」のように、見てもらう表現にとどめる。
   - **匿名の維持**: 氏名・勤務先など運営者を特定する情報は書かない（運営者情報ページの「個人運営」の方針に合わせる）。

注意:

- 実際にXへ投稿する操作は行わない（そのためのツールもない）。あくまで文案の作成のみ。
- デプロイ状況や対象ツールが不明なまま断定した文面を作らない。
- Xプロフィール（bio・固定ポスト）へのリンク追加は、このコマンドの対象外。必要ならユーザーが手動で行う。
