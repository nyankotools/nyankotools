# Maintenance list: tools affected by law / system changes

Tools whose results depend on tax rates, insurance rates, labor law, holiday rules, or other rules that change over time. When a revision is announced (annual tax reform, rate changes in spring, holiday law changes, etc.), check the matching rows here instead of searching the codebase. See [CLAUDE.md](../../CLAUDE.md) for the project-wide premises.

Surveyed on 2026-10-15 by reading the logic (`src/lib/tools/`), dictionaries (`src/i18n/tools/`) and page components. Registry dates are the `updatedAt` at that time.

## How to use

1. On a revision, find the rows whose "Trigger" matches.
2. Update the constant in the "Where" column, **and** the copy that states the year/rate (dictionary `notes` / `introHtml` / glossary), **and** the unit-test expectations.
3. Bump `updatedAt` of the tool in `src/data/tools.ts` and add an entry to `src/data/updates.ts` (see CLAUDE.md: update info is written right before the `develop` → `main` PR).
4. Update this list when a tool is added or its dependency on a rule changes (add a row in the same commit; see the checklist in [adding-a-tool.md](./adding-a-tool.md)).

## Known gaps / ideas

- Nothing automatically warns that a table is stale. A possible safeguard is a Vitest case that fails when the current date passes the stated validity (e.g. 令和9年分) so the table is reviewed; not implemented.
- Regulation wording is held in dictionaries (ja/en), so both locales must be updated together; the English copy should state the basis year as well.
